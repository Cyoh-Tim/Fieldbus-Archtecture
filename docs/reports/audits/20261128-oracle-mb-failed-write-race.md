## 문제

테스트가 `START` 로 사이클 스레드(8ms 주기 `fb_poll`)를 띄운 채 `POLL → RU32 → WU32 → RU32` 를 보낸다.
A20261004-4 결함(어댑터가 원격 쓰기 전에 미러를 고치고 실패해도 되돌리지 않음) 은 그대로인데, 실패한 쓰기와 두 번째 읽기
사이에 백그라운드 poll 이 한 번 끼면 미러가 서버 값으로 다시 채워져 `after == before` 가 되어 통과한다. strict xfail 이라
이 우연 통과는 oracle job 실패(XPASS) 로 나타나고, 반대로 결함이 고쳐진 뒤의 통과는 결함 수정 여부와 무관하게 보인다.

## 재현 (수정 전, `c42c0d7` 빌드, `--runxfail`)

| 조건 | 결과 (테스트 2케이스 × 반복) |
|---|---|
| 부하 없음, 40회 | 40회 모두 `2 failed` (결함대로) |
| CPU 부하 (바쁜 루프 6개), 60회 | 59회 `2 failed`, **1회 `1 failed, 1 passed`** (우연 통과) |

## 정정

- `START` 를 빼고 명시적 `POLL` 만 쓴다. 사이클 스레드가 없으므로 실패한 쓰기 뒤 되읽기 사이에 미러를 바꾸는 것은 어댑터뿐이다.
- 기대값·요청·파라미터·`@known_defect` 표시는 그대로다.
- 확인 (`--runxfail`, 같은 CPU 부하, 80회): 80회 모두 `2 failed`, 실패 메시지 `실패한 쓰기 뒤 읽기: ['R', '0', '17185'] (poll 값 49161, …)` (결함대로).
  표시를 둔 상태의 파일 전체: `34 passed, 3 xfailed`, XPASS 없음.
- 큐 65 (A20261004-4, #237) 수정 PR 의 완료 조건은 바뀌지 않는다. 고쳐진 뒤에는 이 테스트가 결정적으로 통과해야 한다.
