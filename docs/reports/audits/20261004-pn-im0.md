## A20261004-1. I&M0 OrderID 20번째 바이트가 NUL

**문제:** I&M0 레코드의 OrderID(20옥텟 고정)를 19자 문자열 리터럴로 `memcpy` 해서, 리터럴의 종단 NUL 이
20번째 바이트로 들어간다. OrderID 는 VisibleString 이라 0x20–0x7E 만 허용되고 남는 자리는 공백이다. 엔지니어링
도구가 I&M0 를 읽어 GSDML 의 OrderNumber 와 비교하거나 표시할 때 `FB-ARCH-PN-DEV     \0` 으로 보인다.
T12-3(BlockHeader) 은 고쳐져서 I&M0 자체는 사양 형태로 읽힌다.

**근거 (파일:줄, 기준 커밋 `4adbebd`):**
- `stacks/profinet/src/pn_record.c:38` — `memcpy(im + 2, "FB-ARCH-PN-DEV     ", 20)`. 리터럴은 14자 + 공백 5개 = 19자.
- 같은 함수의 `:39` IM_Serial_Number `"SN00000000000001"` 은 정확히 16자라 문제없다.
- GSDML `stacks/profinet/gsdml/GSDML-V2.35-Fieldbus-PN-Device.xml:38` `OrderNumber Value="FB-ARCH-PN-DEV"`.

**재현 (수정 전, `pn_oracle_pipe` + scapy 2.7.0):** Connect 후 index 0xAFF0 Read, 응답 레코드를 `IM0Block` 으로 디섹트.

```
IM0Block.OrderID = b'FB-ARCH-PN-DEV     \x00'
```

오라클 `tests/oracle/test_pn_oracle.py::test_record_read_im0_visible_strings` 를 `--runxfail --tb=line` 으로 돌린 결과:

```
test_pn_oracle.py:433: AssertionError: OrderID b'FB-ARCH-PN-DEV     \x00'
```

**기대값과 출처:** OrderID = `b"FB-ARCH-PN-DEV" + b" " * 6` (20옥텟, 모두 0x20–0x7E), IM_Serial_Number 16옥텟도 같은 규칙.
- Wireshark `plugins/epan/profinet/packet-dcerpc-pn-io.c` `dissect_IandM0_block`: OrderID `c8[20]`, IMSerialNumber `c8[16]` 고정 길이 ASCII.
- p-net `src/device/pf_block_writer.c` `pf_put_str`: 짧은 문자열 뒤를 공백(0x20)으로 채우고 NUL 을 쓰지 않는다. `pf_put_im_0` 이 OrderID·Serial 에 쓴다.
- PI I&M 가이드라인 / IEC 61158-6-10: OrderID 는 VisibleString[20] (원문은 직접 인용하지 못함 — 위 두 독립 구현을 판정 근거로 쓴다).

출처 URL:
- Wireshark: https://gitlab.com/wireshark/wireshark/-/blob/master/plugins/epan/profinet/packet-dcerpc-pn-io.c
- p-net: https://github.com/rtlabs-com/p-net/blob/master/src/device/pf_block_writer.c

**수정 범위:** `stacks/profinet/`, `tests/`.
- `pn_record.c` 의 OrderID 리터럴을 20자로 바꾼다 (공백 6개). 가능하면 `sizeof(literal) - 1 == 20` 을 `_Static_assert` 로 확인한다.
- 단위 테스트 `tests/test_pn_rpc.c` 의 I&M0 검사에 OrderID 20바이트 전체 비교를 더한다 (지금은 앞 14바이트만 본다).

**완료 조건:**
- 오라클 `test_record_read_im0_visible_strings` 가 통과하고 `@known_defect("A20261004-1", …)` 표시를 지운다.
- PN 오라클의 다른 결과(passed·xfailed 수)가 그대로다.
- 스크래치 검증: 리터럴에 공백 하나만 더한 패치에서 이 테스트만 XPASS(strict) 가 되고 나머지는 `8 passed, 36 xfailed` 로 그대로였다.

## 확인 필요 (큐에 넣지 않음)

- **Write RecordDataLength 가 실제 데이터보다 클 때** (`pn_rpc.c` `attach_write_payload`): 남은 바이트만큼 잘라 쓰고 성공을
  응답한다. p-net 은 같은 상황을 PNIORW 에러로 거부한다 (`pf_cmrpc.c`). 기존 동작이라 회귀는 아니며, 거부 PNIOStatus 의
  정확한 코드(ErrorCode1 0xB0 계열)는 IEC 61158-6-10 원문 확인이 필요하다. T12-18(미지원 index 에러) 정리 때 함께 정한다.
- **CTT `step_record_read` fallback** (`tools/ctt/proto/profinet/pn_plugin.c`): 0x8009 가 없으면 NDR 전체를 레코드로 써서
  I&M1–4·미지원 index 시나리오가 옛 형식도 통과시킨다 (T12-0 관점). 오라클이 이 경로를 잡고 있어 제품 결함은 아니다.
  `tools/ctt/` 는 자체 PR 범위 밖이라 후속 작업 후보로만 적는다.
