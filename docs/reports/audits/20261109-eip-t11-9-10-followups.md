## A20261109-1. 표준 객체의 읽기 전용 속성 Set 이 0x0E 가 아니라 0x05 다

**문제:** TCP/IP Interface·Ethernet Link·Port 객체의 있는 속성(읽기 전용)에 Set_Attribute_Single 을 보내면 general status
0x05 (Path destination unknown) 로 응답한다. 0x05 는 경로의 객체·인스턴스가 없다는 뜻이라, 툴은 속성이 없다고 본다.
#192 는 Identity 만 0x0E 로 고쳤다 (오라클이 Identity Vendor ID 만 본다).

**근거:** `stacks/ethernetip/src/eip_cip.c` `handle_object` 끝 (#192 기준 `:702`) — 객체별 Set 처리에 없는 속성은 0x05.
**재현 (오라클, DUT `eip_oracle_adapter`):** `test_set_read_only_standard_object_attribute_not_settable` (`--runxfail`) →
`TCP/IP Status Set 90000500`, `TCP/IP Configuration Capability Set 90000500`, `Ethernet Link Interface Speed Set 90000500`,
`Port Type Set 90000500`. 각 속성의 Get 은 status 0 (속성이 있음).
**기대값과 출처:** OpENer `cipcommon.c` `SetAttributeSingle` — 속성이 있고 `set_bit_mask` 에 없으면 `kCipErrorAttributeNotSetable` (0x0E).
속성이 없으면 0x14. Vol 2 에서 settable 인 TCP/IP attr 3·5·6·13, QoS attr 1–8 등은 이 항목이 바꾸지 않는다 (지금 Set 동작 유지).
**수정 범위:** `stacks/ethernetip/`, `tests/`. 객체별로 "있는 속성 · settable 여부" 표를 두고 Set 은 없음 0x14 / 읽기 전용 0x0E.
쓰이지 않는 `CIP_STATUS_ATTR_READONLY` (0x0A, CIP 에서는 attribute list error) 는 지우거나 이름을 바로잡는다.
**완료 조건:** 오라클 4개 통과 (`A20261109-1` 표시 삭제). 기존 settable 속성 Set 은 그대로 (단위 테스트).

## A20261109-2. 거부된 RegisterSession 이 그 연결의 세션 표시를 지운다

**문제:** 이미 세션을 가진 TCP 연결이 잘못된 RegisterSession (버전 ≠ 1 또는 옵션 ≠ 0) 을 보내면 응답 핸들 0 이
`c->session` 에 들어간다. 세션 테이블에는 세션이 남아 있어 그 핸들로 SendRRData 는 계속 되지만, `eip_stack_session_up`
은 그 클라이언트를 세션 없음으로 보고, 어댑터는 (`adapters/ethernetip/ethernetip_adapter.c:1011`) 연결 상태를 내린다.
**근거:** `stacks/ethernetip/src/eip_stack.c:588-592` — `rc == 0 && cmd == REGISTERSESSION` 이면 응답 핸들을 그대로 대입
(status 를 보지 않음). TLS 경로 (`eip_sec.c`) 도 같은 방식인지 함께 본다. 출처 #190 "발견한 다른 문제" 4.
**기대값과 출처:** OpENer `encap.c` `HandleReceivedRegisterSessionCommand` — 세션은 소켓에 묶여 있고, 거부 응답(핸들 0)은
이미 등록된 세션을 건드리지 않는다. 세션은 UnRegisterSession·연결 종료로만 없어진다.
**수정 범위:** `stacks/ethernetip/`, `tests/`. 응답 status 가 0 일 때만 `c->session` 을 바꾼다.
**완료 조건:** 단위 테스트: 등록 → 버전 2 RegisterSession (0x0069) → `eip_stack_session_up` 1, 원래 핸들 SendRRData 성공 (TCP·TLS).
오라클 없음 (내부 상태).

## A20261109-3. Identity Protection Mode (attr 19)·클래스 속성·TCP/IP attr 5 호스트 값 (낮음)

#183 답 (https://github.com/Cyoh-Tim/Fieldbus-Archtecture/issues/183#issuecomment-6731847447) 에서 #192 범위 밖으로 미룬 것.
- **Protection Mode:** Wireshark `packet-cip.c` Identity 인스턴스 표 `19 "Protection Mode"` (UINT16 LE, 비트 `0x0007`
  Implicit Protection Setting, `0x0008` Explicit Protection Setting). attr 17 은 "Assigned Geographic Location" (STRINGI).
  #192 뒤 attr 17·19 Get 은 모두 0x14. `cfg.protection_mode` (0 이 아니면 Set/Reset 거부) 를 이 비트로 옮기는 규칙은 독립 근거가
  없다 — 구현 PR 에서 `[Claude 확인 요청]` 으로 정한다.
- **클래스 속성 (instance 0):** #192 뒤 TCP/IP·QoS class attr 1 Get 은 0x05. OpENer class revision: TCP/IP 4, Ethernet Link 4,
  QoS 1, Identity 1 (`CreateCipClass`). Port 는 OpENer 에 없어 근거 없음. 리비전은 그 리비전의 필수 속성을 갖춘 뒤 정한다.
- **TCP/IP attr 5:** 비루프백이면 mask·gateway·DNS 가 0 (#192 "발견한 다른 문제" 1, `eip_cip.c:446`). OpENer 는 OS 에서 읽는다
  (`networkhandler` 포트 계층). 스택 밖 조회(netlink/ioctl)가 필요하다.
**수정 범위:** `stacks/ethernetip/`, `tests/`. **완료 조건:** 단위 테스트 (Get attr 19 WORD, 클래스 attr 1–7, attr 5 가 호스트 값).
