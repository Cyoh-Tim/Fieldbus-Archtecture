# 2026-11-21 — 주기 지터 장시간 측정 절차 (A코어 Linux, PREEMPT_RT 없음)

- 출처: 담당자 결정 (2026-11-21). 담당자가 4코어 400% CPU 부하에서 지터가 크게 늘지 않는 것을 직접 확인했고,
  "PREEMPT_RT 없이 Linux A코어만으로" 주기 구동 프로토콜(PROFINET RT Class 1, EtherNet/IP Class 1)을 가져가기로 했다.
  이 절차는 그 판단을 **다시 돌릴 수 있는 측정 기록**으로 남기기 위한 것이다.
- 큐: 135 (A20261121-1, 측정 스크립트). 이 문서가 그 항목의 사양이다.
- 인증 결과가 아니다. PI / ODVA 공식 시험의 허용치는 이 저장소에 없다. 여기서 정하는 기준은 회귀 감지선과 상호운용 여유다.

## 1. 무엇을 재나

PLC 가 실제로 보는 것은 **장치가 보낸 주기 프레임 사이 간격**이다 (위상은 RT Class 1·Class 1 에서 따지지 않는다).
그래서 1차 지표는 선(wire) 위 간격이고, 데몬 내부 지표는 원인 구분용이다.

| 지표 | 어디서 | 설명 |
|---|---|---|
| 프레임 간격 분포 | 패킷 캡처 | 장치 송신 프레임의 연속 간격. 최소·p50·p99·p99.9·최대, `|간격 − 주기|` 분포 |
| 늦은 간격 수 | 패킷 캡처 | 간격 > 1.5 × 주기 인 수 (기존 soak 소프트 예산, `docs/soak_report_20260910_jitter.md`) |
| 감시 시간 초과 | 패킷 캡처·PLC | 간격 > 주기 × DataHoldFactor(PN) 또는 RPI × multiplier(EIP). 0 이어야 한다 |
| 마감 놓침 / 지터 요약 로그 | 데몬 stderr | T7 (큐 57) D안 이후. 마감 놓침 줄 수, 지터 요약 줄의 초과 횟수·최대 편차 |
| 최대·평균 기상 지연, 최대 지연 | `fb_health` `reserved[]` | T7 이후 (`FB_HEALTH_*`). 있으면 기록 |

## 2. 판정선

| 구분 | 기준 | 근거 |
|---|---|---|
| 상호운용 (필수) | 감시 시간 초과 0회, 간격 > 1.5 × 주기 0회 | PLC 연결 유지. 기존 soak 소프트 예산 |
| 회귀 감지선 (기록) | `|간격 − 주기|` 최대 ≤ 100µs, p99.9 기록 | `docs/design.md` 5장 "최대 지연 편차 0.1ms" (에이징 측정 기록) |

회귀 감지선을 넘으면 실패가 아니라 **기록하고 원인을 본다** (어느 부하에서, 마감 놓침인지 기상 지연인지).
이전 측정보다 p99.9 나 최대가 뚜렷이 나빠지면 회귀로 본다.

## 3. 환경 기록 (측정마다)

- 보드·CPU (모델, 코어 수, 클럭), 메모리
- 커널 버전과 선점 모델 (`uname -a`, `/sys/kernel/debug/sched/preempt` 또는 `CONFIG_PREEMPT*`), PREEMPT_RT 여부
- CPU 주파수 정책 (`cpupower frequency-info` 또는 `scaling_governor`), 온도 (측정 전·후)
- NIC 모델·드라이버, 인터럽트 결합 설정 (`ethtool -c`), 하드웨어 타임스탬프 지원 (`ethtool -T`)
- 데몬 커밋, config (`cycle_ms`, 프로토콜, 포인트 수), 스케줄링 (기본 SCHED_OTHER 인지, nice 값)
- 상대편: 실제 PLC (모델·펌웨어·설정 주기) 또는 소프트웨어 마스터 (`examples/sw_master.py`, 다른 호스트인지 루프백인지)

## 4. 부하 시나리오

각 시나리오 **1시간**, 혼합은 **2시간** (설계 문서의 1~2시간 에이징과 맞춘다). 순서대로 돌리고 사이에 1분 쉰다.

| 이름 | 부하 | 도구 예 | 보는 것 |
|---|---|---|---|
| `idle` | 없음 | — | 기준선 |
| `cpu` | 전 코어 100% (4코어면 400%) | `stress-ng --cpu 0 --cpu-method matrixprod` | 담당자 측정 재현 |
| `net` | 같은 NIC 로 대량 트래픽 (수신·송신) | `iperf3 -c <peer> -t 3600 -P 4`, 다른 호스트에서 `iperf3 -R` | 네트워크 인터럽트·softirq. PROFINET 인증의 Netload 시험과 가장 가까운 조건 |
| `io` | 디스크 I/O | `stress-ng --hdd 2 --io 2` | 블록 I/O 인터럽트, 쓰기 지연 |
| `vm` | 메모리 대역폭·페이지 | `stress-ng --vm 2 --vm-bytes 75%` | 캐시·TLB 압박 |
| `mix` | 위 넷을 동시에 (각 강도는 절반) | 위 조합 | 최악에 가까운 조건, 발열 |

도구가 없으면 그 시나리오는 "건너뜀" 으로 기록한다 (실패로 세지 않는다).

## 5. 측정 방법

1. **상대편으로 연결을 연다.** PROFINET 은 AR 이 있어야 장치가 RT 프레임을 보내므로 실제 PLC 가 필요하다.
   PLC 가 없으면 EtherNet/IP Class 1 로 잰다: 다른 호스트에서 `examples/sw_master.py` 의 Class 1 모드로 Forward Open
   (루프백은 NIC 인터럽트를 거치지 않으므로 `net` 시나리오에는 쓰지 않는다).
2. **캡처한다.** 장치 NIC 에서 `tcpdump -i <if> -w <file>.pcap` (PN: `ether proto 0x8892`, EIP Class 1: `udp port 2222`).
   - 하드웨어 타임스탬프가 되면 `-j adapter_unsynced` 를 쓴다. 안 되면 소프트웨어 타임스탬프이고, 그 자체 지터가
     결과에 섞인다는 점을 기록한다. 가능하면 미러 포트나 별도 캡처 호스트가 더 정확하다.
   - 장치가 보낸 프레임만 고른다 (PN: 송신 MAC 과 입력 CR 의 FrameID, EIP: 장치 IP·T→O 연결).
3. **데몬 로그를 남긴다.** 데몬 stderr 를 파일로 받는다. T7 이후면 마감 놓침·지터 요약 줄을 센다.
4. **분석한다.** 캡처 타임스탬프로 연속 간격을 구해 1장의 지표를 낸다. 결과는 시나리오별 JSON 한 개와 표 한 줄.

## 6. 결과 양식

`docs/reports/jitter_<YYYYMMDD>/` 에 시나리오별 JSON·원본 로그와 아래 표를 둔다 (pcap 은 크면 요약만 커밋한다).

| 시나리오 | 시간 | 프레임 수 | 간격 p50 | p99 | p99.9 | 최대 | `|간격−주기|` 최대 | > 1.5×주기 | 감시 초과 | 마감 놓침 줄 | 지터 요약 줄 |
|---|---|---|---|---|---|---|---|---|---|---|---|

표 위에 3장의 환경 기록을 붙인다. 판정은 2장 기준으로 "상호운용 통과/실패" 와 "회귀 감지선 이내/초과(원인)" 를 따로 적는다.

## 7. 큐 135 (A20261121-1) 의 범위

이 절차를 한 번에 돌리는 스크립트를 `tools/jitter/` 에 만든다.
- 실행기 (셸): 시나리오 목록·시간·인터페이스·상대편을 인자로 받고, 3장 환경을 자동 기록하고, 부하 도구를 띄우고 내리고,
  캡처와 데몬 로그를 시나리오별로 저장한다. 루트 권한·도구가 없으면 무엇을 건너뛰었는지 기록하고 계속한다.
- 분석기 (Python, 표준 라이브러리만): pcap 을 읽어 PN RT (EtherType 0x8892, FrameID·송신 MAC) 또는 EIP Class 1 (UDP 2222,
  송신 IP) 의 장치 프레임 간격을 계산해 6장의 JSON 과 표 한 줄을 낸다. 데몬 로그의 마감 놓침·지터 요약 줄도 센다.
- 분석기 자체 시험: `--self-test` 옵션으로 합성 pcap (간격을 아는 프레임 몇 개) 을 만들어 p99·최대·> 1.5×주기 계산을 확인한다
  (CI·`CMakeLists.txt` 에 등록하지 않아도 PR 설명에 출력을 붙여 검증할 수 있게).
- 새 C 실행 파일과 `CMakeLists.txt` 변경은 넣지 않는다 (기존 `multiproto_daemon`·`examples/fake_sensor_app` 과 `examples/sw_master.py` 를 쓴다).
