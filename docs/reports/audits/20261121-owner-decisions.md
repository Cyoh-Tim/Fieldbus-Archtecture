# 2026-11-21 — 담당자 결정: T7 사이클 경고를 "마감 놓침" 과 "지터" 로 나눈다

- 출처: 2026-11-21 실행의 #227 (T7, 큐 57) 검증 "확인 필요"
- 판단: 검증 담당 제안 D → **담당자 결정 (2026-11-21): "D안으로 결정하되, 지터 100us는 눈여겨볼만한 수치인 것 같아"**

## 배경 (검증 근거)

#227 head `2254496` 은 사이클마다 편차 `max(wake, elapsed − cycle)` 가 `cycle_warn_us` (기본 100) 를 넘으면
`LOG_WARN("fb_api", "cycle 초과: …")` 를 제한 없이 찍는다. `main` + #227 로컬 CI 에서 `cycle 초과` 줄 수가
`sw-master-soak` 0 → 823, `codesys-dut` 0 → 119, daemon `ctest` 0 → 526 으로 늘었다. 거의 모두 poll 이 아니라
기상 지연이다 (예: `elapsed=12us wake=106us`, 편차 최소 101µs·중앙값 127µs·최대 2814µs — 8ms 를 넘은 사이클 없음).
"cycle 초과" 라는 문구가 처리 시간이 주기를 넘은 것처럼 읽히는 것도 문제였다.

- 루프는 절대 시각(`TIMER_ABSTIME`)으로 다음 목표를 잡으므로 wake + elapsed 가 주기 안이면 지연이 쌓이지 않는다.
  넘으면 그 사이클의 마감을 놓치고 `next = now` 로 다시 잡는다.
- `docs/design.md` 5장의 "최대 지연 편차 0.1ms" 는 기준 장비의 측정 기록 (회귀 감지 기준선) 이다.

## 결정 (D안)

| 종류 | 조건 | 출력 |
|---|---|---|
| 마감 놓침 | 한 사이클의 `wake + elapsed > cycle_ms × 1000` µs | 사이클마다 `LOG_WARN` (원인이 보이게 wake·elapsed·cycle 을 함께) |
| 지터 | 편차 > `cycle_warn_us` (기본 **100µs 유지**) | `fb_health` 의 최대·평균·초과 횟수로 누적. 로그는 **1초에 최대 한 번 요약** `LOG_WARN` (그 구간의 초과 횟수·최대 편차) |

- 담당자 의견대로 100µs 지터는 지켜볼 수치이므로 기본값을 올리지 않고, 요약 로그로 계속 보이게 한다 (조용히 숨기지 않는다).
- 두 로그의 문구를 구분한다 (예: "사이클 마감 놓침: wake=…us elapsed=…us > cycle=…us", "지터 요약: 1초간 N회 > 100us, 최대 …us").
- T7 완료 조건: 9ms `poll_cycle` 은 마감 놓침 경고를 내고, `fb_health` 로 최대 지연을 µs 로 읽는다. µs 기준(`cycle_warn_us`) 은 설정할 수 있다.
- 범위는 큐 57 그대로 (`core/`, `include/fb_api.h`, `tests/`). #227 에 같은 내용을 `[담당자 결정]` 으로 남겼다.
