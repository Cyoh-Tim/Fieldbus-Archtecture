## A20261003-2. DCP Get 이 요청한 블록 대신 Identify 블록 7개 전체를 돌려준다

**문제:** DCP Get.req(FrameID `0xFEFD`, ServiceID 3)에 무엇을 요청하든 장치가 Identify.res 와 같은 블록
7개를 ServiceType Success 로 돌려준다. 지원하지 않는 옵션을 요청해도 오류 블록이 없다. 엔지니어링 도구는
요청한 블록 하나를 기대하므로, 응답 첫 블록만 보는 구현은 다른 값을 읽고, 지원 여부를 묻는 Get 에는 거짓
"성공" 이 돌아간다. T12-2(BlockInfo) 는 고쳐져서 블록 자체는 사양 형태로 읽힌다.

**근거 (파일:줄, 기준 커밋 `a15b3e9`):**
- `stacks/profinet/src/pn_dcp.c:531-537` — `sid == PN_DCP_GET` 이면 요청 페이로드를 보지 않고
  `build_identify_blocks` 결과를 `PN_DCP_RESP_SUCCESS` 로 보낸다.
- 저장소 입문서 `docs/protocols/profinet.md:925-930` 도 같은 차이를 "[차이, 검증: 하네스]" 로 적어 두었다
  (참고용, 판정 근거 아님).

**재현 (수정 전, `pn_oracle_pipe` + scapy 2.7.0):** NameOfStation 만 요청.

```
요청 fefd 03 00 00006001 0000 0002 0202
응답 fefd 03 01 00006001 0000 005e 0201…    (ServiceType 1, DCPDataLength 94)
scapy 블록 (Option, Suboption): (2,1) (2,2) (2,3) (2,4) (1,2) (1,1) (2,5)
```

IP 만(`0102`), 둘 다(`0202 0102`), 지원하지 않는 옵션(`0401`)을 요청해도 Xid 외에는 응답이 같다.
오라클을 `--runxfail --tb=line` 으로 돌린 결과:

```
test_pn_oracle.py:801: AssertionError: 요청 [(2, 2)] 에 응답 블록 [(2, 1), (2, 2), (2, 3), (2, 4), (1, 2), (1, 1), (2, 5)]
test_pn_oracle.py:819: AssertionError: 응답 블록 [(2, 1), (2, 2), (2, 3), (2, 4), (1, 2), (1, 1), (2, 5)] (Control/Response 하나 기대)
```

**기대값과 출처:**
- Get.req 블록은 길이 필드 없는 Option(1) Suboption(1) 쌍의 목록이고, Get.res 는 요청 쌍마다 블록 하나다.
  - Wireshark `plugins/epan/profinet/packet-pn-dcp.c` `dissect_PNDCP_PDU`: Get+Request 는 "Selectors" 로
    `dissect_PNDCP_Option` 만 읽고, Response 는 `dissect_PNDCP_Block` 으로 읽는다.
  - p-net `src/common/pf_dcp.c`: Get.req 의 쌍마다 `pf_dcp_get_req` 를 한 번씩 불러 그 블록만 넣는다.
- 줄 수 없는 항목은 GetNegResBlock: Option Control(`0x05`), Suboption Response(`0x04`), DCPBlockLength 3,
  요청 Option·Suboption, BlockError (`0x01` Option unsupp. / `0x02` Suboption unsupp.). 블록 앞 BlockInfo 없음.
  - Wireshark `dissect_PNDCP_Suboption_Control` 의 `PNDCP_SUBOPTION_CONTROL_RESPONSE` 분기, `pn_dcp_block_error`.
  - scapy `scapy.contrib.pnio_dcp.DCPControlBlock` (`response`, `response_sub_option`, `block_error`).
  - p-net `pf_dcp_get_req` 의 GetNegResBlock.
- Get 서비스 자체는 지원하므로 ServiceType 은 Success(1). 5 는 "ServiceID not supported" 다.
- 판정 헬퍼 자체 시험: scapy 로 만든 사양 형태 응답(`05 04 0003 04 01 01`, `02 02 000c 0000 "oracle-dut"`)을
  같은 디섹트 경로에 넣으면 `[(5,4)]`, BlockError 1, `[(2,2)]`, `oracle-dut` 로 읽힌다.
