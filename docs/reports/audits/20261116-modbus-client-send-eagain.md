## A20261116-1. 클라이언트 요청 송신이 `EAGAIN` 이면 연결을 버린다 (낮음)

**문제:** 클라이언트 소켓은 non-blocking 인데 (`client_connect` 의 `set_nonblock`), 요청을 보내는 `send_all` 은 `EINTR` 만 다시 시도하고
`EAGAIN` 이면 실패로 돌려준다. 호출부는 그때 `client_drop(s, -EIO)` 로 소켓을 닫는다. 서버(PLC)가 잠시 읽지 않아 송신 버퍼가 차면
요청이 다 나가기 전에 연결이 끊기고 재연결 백오프로 들어간다.
**근거 (`1d071a0`):** `stacks/modbus/src/mb_stack.c:620` `set_nonblock`, `:879-895` `send_all`, 호출부 `:1092` (`client_txn`), `:1226`
(`mb_stack_client_write_regs`), `:1301` (`mb_stack_client_write_bits`).
**영향:** 클라이언트는 요청 하나(최대 260 바이트)를 보내고 응답을 기다리므로 송신 버퍼가 실제로 찰 일은 드물다 — 그래서 낮음.
서버 쪽 같은 종류 결함(T9-8) 과 EIP Originator (A20261028-1 의 `originator_sendrr`) 와 같은 기준으로 맞춘다.
**기대값:** 요청을 다 보낼 때까지 쓰기 가능을 기다린다 (`poll(POLLOUT)`, 남은 트랜잭션 타임아웃 안). 타임아웃이면 지금처럼 `-EIO`·재연결.
**수정 범위:** `stacks/modbus/`, `tests/`. **완료 조건:** 단위 테스트: 서버가 읽지 않아 클라이언트 송신 버퍼가 찬 상태에서, 서버가 다시 읽기
시작하면 요청이 끝까지 나가고 트랜잭션이 성공한다 (타임아웃 안).
